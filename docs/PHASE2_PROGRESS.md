## Verified v2 interface (from original SQL, NOT live database)

- `public.pointplus_submit_mission(p_mission uuid, p_participant uuid, p_idempotency_key text, p_proof_text text default null, p_proof_path text default null)` returns submission UUID.
- `public.pointplus_review_mission(p_submission uuid, p_approve boolean, p_note text default null)` returns submission UUID.
- Personal Space auto-reviews during submission; other Spaces create `mission.submitted` notifications.
- Review locks submission `FOR UPDATE`, rejects second review, uses atomic `pointplus_private.post_points`, triggers `mission.review` notification; rejection requires a note.
- `mission_submissions` immutable to clients; authorized writes only through RPC. Submissions unique by `(created_by,idempotency_key)` and pending/approved occurrence key.
- `point_wallets` / `point_transactions` are RLS-protected read-only to clients.
- `notifications` allows recipient-specific `SELECT` and `UPDATE(read_at)`.
- `pointplus-evidence` bucket is private, 5 MB limit and restricts uploads to authenticated user's folder. Never use public URLs.
- Spaces: `personal`, `couple`, `family`. There is no `friends` or `group` enum value.

## Security/release blockers

1. Connect the **correct** Supabase project to the connector with read rights; validate schema, RLS, private storage, policies, SQL function signatures and Realtime publication. Do not run against an unrelated project.
2. Run end-to-end tests with separate adult users, guardians and children, cross-Space probing, duplicate submissions and concurrent reviews.
3. Verify new route visual accessibility and errors at mobile widths. Correct CI issues before deployment.
4. v2 schema has no member exit/removal/block/report RPCs; write a separate least-privilege migration proposal only if these social safety features are explicitly approved. Do not claim these capabilities are supported.
5. SQL v2 creates submission/review notifications but not dedicated notifications for mission assignment. No duplicate client-side notification writes were introduced.
6. No Supabase Realtime publication was verified; a visible-tab polling fallback is used instead of unsafe subscriptions.
7. `loadMissionSubmissions` currently displays a recent limited history (100 records); strict eligibility/recurrence is enforced solely by database RPC.

No database migrations were applied. No automatic merge.
